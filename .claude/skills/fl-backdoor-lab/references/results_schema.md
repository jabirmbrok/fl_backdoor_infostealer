# Results schema

## What each run writes (existing code)

| Path | Written by | Contents |
|---|---|---|
| `results/<run>/history.json` | all FL scripts | list of per-round rows. Clean FL: `round, val_accuracy, val_macro_f1`. Backdoor: `round, clean_accuracy, clean_macro_f1, asr` (**test** split). Defense: the same plus `defense` and, for Multi-Krum, `selected_clients`. |
| `results/<run>/final_metrics.json` | backdoor + defense | `clean_test_metrics` (loss, accuracy, macro_f1, per-class, confusion matrix), `asr_source_to_target`, `source_label`, `target_label`, `trigger_channel`, `poison_rate` |
| `results/<run>/test_metrics.json` | clean FL + centralized | the same metric block for the clean test set |
| `results/<run>/*.pt` | all | `final_model.pt`, `final_backdoor_model.pt`, `best_model.pt` |
| `results/trigger_control/<name>.json` | trigger control | `source_test_count`, `clean_test_accuracy`, `clean_test_macro_f1`, `clean_source_target_prediction_rate`, `triggered_source_target_prediction_rate` |
| `results/logs/<name>.log` | the `.bat` drivers | stdout |

Nothing above should be edited by hand.

## `results/runs.csv` — generated by `export_runs.py`

One row per run, the single input to every table.

| column | values |
|---|---|
| `exp_id` | the results directory name (or trigger-control file stem) |
| `scenario` | `backbone_sel`, `clean_fl`, `trigger_control`, `backdoor_fedavg`, `backdoor_defense`, `split` |
| `variant` | `-`, `at2fb`, `at2fb-p30-s12`, `at2fb-r50`, `r50`, `vd2sc`, `at2fb-contrast`, `<rep>-<backbone>` |
| `channel` | `none`, `red`, `green`, `blue`, `full` |
| `defense` | `none`, `clipping`, `median`, `trimmed_mean`, `multikrum` |
| `seed` | 42, 123, 2026, 7, 99 |
| `clean_acc`, `macro_f1` | 4 decimals, in [0, 1] |
| `asr_hits`, `asr_n` | raw counts (hits out of 15); empty for `backbone_sel` and `clean_fl` |
| `notes` | provenance and warnings; the exporter writes `<<` markers for rows that need review |

The group key used by every downstream script is `(scenario, variant, channel, defense)` with the
seed as the replicate. Two rows may not share key + seed — that is why re-runs get their own variant
tag rather than overwriting the original.

## `results/tables/` — generated, never edited

`summary.csv|md|tex` (aggregate.py), `stats.md` (stats_tests.py), `selection_stats.md`
(selection_stats.py), `channel_stats.csv|md` (channel_stats.py). The paper `\input`s the `.tex`.

## `results/paper_reported.csv`

The numbers exactly as printed in the submitted paper, for `aggregate.py --compare-paper`. As of the
audit, all 21 groups reproduce from `runs.csv` to within 5e-4. If a comparison starts failing, the
cause is a changed run, not a changed script.

## Legacy summary CSVs

`backbone_summary_seed42.csv`, `backdoor_sweep_summary.csv`, `defense_summary.csv`,
`trigger_control_summary.csv`, `multiseed_core_raw.csv`, `multiseed_core_mean_std.csv` were produced
by `scripts/collect_*.py`. They are kept for provenance and are consistent with `runs.csv`, but new
analysis should not read them: they use different schemas and store ASR as ratios.
