# Experiment protocol (this repository)

Authoritative description of what the code does: `docs/CODE_FACTS.md`.
Known paper-vs-code mismatches: `docs/DISCREPANCIES.md`.

## Launching each run type

Every script takes a single `--config`. Run from the repo root.

| Run type | Command |
|---|---|
| split creation | `python scripts/create_splits.py` (edit the seed inside / pass its arguments) |
| backbone selection | `python scripts/train_centralized.py --config configs/backbone/<rep>_<backbone>_seed42.yaml` |
| clean FL | `python scripts/train_fl_clean.py --config configs/multiseed/fl_clean_seed<N>.yaml` |
| backdoor, FedAvg | `python scripts/train_fl_backdoor.py --config configs/backdoor_sweep/<ch>_p20_s10_r50.yaml` |
| backdoor, defense | `python scripts/train_fl_backdoor_defense.py --config configs/defense/<ch>_<defense>.yaml` |
| trigger control | `python scripts/evaluate_trigger_control.py --config configs/trigger_control/<ch>_clean_control.yaml` |

After any run: `python .claude/skills/fl-backdoor-lab/scripts/export_runs.py --force`.

## Fixed setup (do not change silently)

5 families x 100 samples; stratified 350/75/75 **re-drawn per seed**; 128x128 RGB-stack
(R = API 16x16 tile, G = network 28x28 tile, B = fusion); ResNet18 from scratch; AdamW, lr 1e-4,
weight decay 1e-4, batch 16, cross-entropy, no augmentation; FedAvg over 5 IID clients of 70 samples
(14 per family), 50 rounds x 2 local epochs, final-round model reported; attack AgentTesla(0) ->
FormBook(1) by client 0 with pure data poisoning, white 12x12 trigger bottom-right, poison rate 0.20
of the attacker's 14 source samples = 2 images, resampled every round; Multi-Krum f = 1, |S| = 2;
ASR over the 15 source-class test samples.

Seeds 42, 123, 2026 are the paper's. Seeds 7 and 99 are the camera-ready additions — each needs its
own `dataset/splits/split_rgb_seed<N>.csv` created first, or the run will silently reuse another
seed's split.

## Writing a new config

Copy the closest existing file into `configs/camera_ready/` and change only what the matrix row
requires. Never edit a config that produced a submitted result. Keep `output_dir` equal to the
`exp_id` in the run matrix so the exporter picks it up without a new parsing rule.

```yaml
seed: 7
output_dir: results/fl_backdoor_rgb_resnet18_blue_p20_s10_seed7
data:  { dataset_root: dataset/processed/dataset_rgb_stack_combined,
         split_csv: dataset/splits/split_rgb_seed7.csv, image_size: 128 }
model: { name: resnet18, num_classes: 5 }
train: { batch_size: 16, lr: 0.0001, weight_decay: 0.0001 }
fl:    { num_clients: 5, rounds: 50, local_epochs: 2, eval_every: 1, client_col: client_iid }
attack:{ source_label: 0, target_label: 1, malicious_client: 0, poison_rate: 0.20,
         trigger_channel: blue, trigger_size_ratio: 0.10, trigger_location: bottom_right }
```

## Run matrix tiers

`experiments/run_matrix.csv`, regenerated by `python experiments/make_run_matrix.py`.

- **Tier 0 (40 rows, done)** — everything already in the repo, including three finished ablations
  that never made it into a table (D6). `export_runs.py` covers all of them.
- **Tier 1 (8 rows)** — fixes from the audit. The clean FL seed-42 re-run at 50 rounds / 2 local
  epochs plus its four trigger controls (D1), and optionally the three opacity-blend backbones on
  the RGB split (D2). These carry the variant tags `r50` / `at2fb-r50` / `-rgbsplit` so they can sit
  next to the originals in runs.csv instead of colliding.
- **Tier 2 (36 rows)** — the cheap additions that answer reviewers B and C: seeds 7 and 99 for the
  core scenarios, red/green across seeds, and the non-Multi-Krum defenses across seeds.
- **Tier 3 (27 rows)** — optional: second source-target pair, contrast-matched trigger, backbone
  selection across seeds.

## New run types that need code

**Contrast-matched trigger (`at2fb-contrast`, Tier 3).** `apply_square_trigger` currently writes a
constant `value=1.0`. For this variant, add the same intensity delta to each channel instead, chosen
from the per-channel means in `results/tables/channel_stats.csv`, so red / green / blue triggers
are equally visible. This is the experiment that separates the saliency explanation from the
channel-semantics explanation — see the closing note of `channel_stats.md`.

**Second pair (`vd2sc`, Tier 3).** `source_label: 4` (Vidar), `target_label: 3` (StealC). No code
change; ASR is then computed over the 15 Vidar test samples.

**Multi-Krum selection logging.** Already implemented — `selected_clients` is written into each
history row by `train_fl_backdoor_defense.py`. `selection_stats.py` reads it.
